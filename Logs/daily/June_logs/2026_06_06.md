**Daily Log**

**Anneal V2 — Debug / Architecture Session Notes**

**Overview**
session was focused on resolving structural inconsistencies in Anneal V2 related to trajectory generation, time encoding, and model/data boundary separation. Several issues were identified involving variable ownership, implicit globals, and ambiguous trajectory semantics.

**Issues Found**

**Global state leakage (critical)**

**t_traj was temporarily assigned as a function during testing**:

-t_traj = generate_random_trajectory

**This leaked into runtime scope and caused**:

-tensor/function type mismatch

-failure inside time_encoder (ndim attribute error)

**Implicit variable dependency in model**

-time_encoder() referenced t_traj without explicit input

-Created hidden dependency on external/global state

-Violated explicit data flow principles

**Trajectory / target ambiguity**

pos_target = pos confirmed as ground truth trajectory

Confusion arose from treating trajectory as a transformation stage instead of dataset output

“trajectory” was overused as an abstract shared concept across layers (removed)

**Redundant / conflicting naming**

-pos_target vs initial_pos vs P_d caused semantic overlap (migration/refactor occurence)

-Misleading equivalence between anchor state and dataset state

**Visualization API confusion**

-trajectory argument was ambiguous and redundant

**Mixed responsibilities between**:

-ground truth (pos_target)

-predictions (pos_pred)

-internal state (P_d)

**Fixes Applied**

-Enforced explicit data flow

-t_traj must always be passed explicitly

-removed any implicit or global access patterns

**Corrected model inputs**
**Model now consumes**:

-t_feat, P_d, branch_embed

-t_traj is never used inside model directly

-time encoding happens through t_feat

-Cleaned trajectory generator role

-t_traj, pos_target = generate_random_trajectory()

-generator is sole source of trajectory data

-no runtime overrides allowed

**Visualization clarified**

**Standardized interface**:

-visualize_trajectory(pos_target, pos_pred, latent_uncertainty, branch_out, P_d, loss)

-visualization consumes outputs only

-no ambiguity around “trajectory” argument

**Architectural Principles Established**
**Data ownership separation**

-t_traj, pos_target → dataset layer

-t_feat → model feature space

-P_d → internal model anchor

**No implicit global state**

all dependencies must be passed explicitly
no runtime shadowing or test scaffolding leakage

**Raw vs encoded separation**

raw trajectory time ≠ encoded time features
t_feat is the only model-facing time representation

**Model boundary rule**

-model consumes inputs only

-model never imports or constructs dataset values

**Key Insight**

A major source of instability was traced to semantic overlap between trajectory concepts across layers, combined with implicit global variables introduced during debugging. t_traj_ref, was being fed into time encoding within the model layer instead of t_feat.  migration/renaming artifact.

**Outcome**

-Removed hidden state leakage

-Clarified data vs model vs visualization boundaries

-Established explicit data contract between generator → model → loss → viz pipeline

**Summary**
Anneal V2 now enforces explicit separation between trajectory generation, feature encoding, and model evolution, eliminating implicit state dependencies and variable shadowing issues.
